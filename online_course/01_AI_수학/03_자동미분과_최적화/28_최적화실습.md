# 28-최적화실습
## 학습 포인트
직접 구현한 최적화 코드를 실행하고 SciPy `optimize` 패키지와 비교. 테스트 함수 F3에 초기값 `X0=(-2,3)`을 주고 `minimize`를 호출하며 `method`로 conjugate gradient를 지정. SciPy 함수 인터페이스가 만든 함수와 유사.
SciPy `minimize`와 직접 만든 `minimize` 함수의 결과 경로를 비교해 구현이 잘 작동하는지 확인. 이후 Steepest Descent와 Conjugate Gradient의 반복 횟수와 이동 경로 차이를 비교.
## SciPy Optimize 실험
실험 대상은 지난 시간 애니메이션에서 사용한 테스트 함수 `F3`다. 시작점은 `X0=(-2, 3)`으로 두며, SciPy `optimize` 패키지의 `minimize`를 사용. `method`는 conjugate gradient로 지정하고, `callback`은 해를 찾아가는 과정을 저장하기 위한 보조 함수로 사용.
실행 결과는 `optimization terminated successfully`로 종료되며, 최적점은 `(2, 4)`. 그래프에서는 `(-2, 3)`에서 출발해 골짜기를 돌아 `(2, 4)`까지 도착하는 빨간 경로가 표시.
## 직접 만든 Minimize 함수
직접 구현한 함수도 같은 방식으로 호출. `F3`, `X0`를 넘기고, `method`는 `CGPR`로 지정. 이는 Conjugate Gradient의 Polak-Ribiere 방식이며, SciPy의 conjugate gradient와 비교하기 위해 같은 계열의 방식을 사용했음.
Fletcher-Reeves 방식은 Equation 2, 3을 기준으로 직접 구현. Polak-Ribiere 방식은 제공된 구현과 비교.
`jac`에는 테스트 함수에서 손으로 미분해 만들어 둔 `DF3`를 넣어 gradient를 제공. `line_search`는 Golden Section Search를 사용하며, delta는 `10^-3`으로 지정했음.
## 실행 로그와 결과
직접 만든 최적화 함수를 실행하면 다음 흐름이 확인.
- `start optimization` 메시지가 나옴
- initial point는 `(-2, 3)`
- method는 Conjugate Gradient Polak-Ribiere다
- iteration 1, 11, 21처럼 반복 로그가 출력
- gradient 크기는 처음 약 `420`에서 `9`, `5` 등으로 줄다가 마지막에는 `0`이 됨
- cost function도 `14`에서 점점 떨어져 최종적으로 `0`이 됨
- 최종 `x` 위치는 `(2, 4)`가 되어 최적화가 성공
SciPy 경로는 빨간색, 직접 만든 함수의 경로는 녹색으로 표시되며, 두 경로는 대부분 유사. 세부 차이는 line search 방식이 서로 다르기 때문.
## Steepest Descent와 Conjugate Gradient 비교
마지막 실험에서는 테스트 함수 `F2`에 대해 `minimize`를 두 번 호출. 한 번은 Steepest Descent, 한 번은 Conjugate Gradient Fletcher-Reeves 방식.
확인된 비교 결과:
- Steepest Descent는 약 26번 반복
- Conjugate Gradient는 약 3번만 반복
Steepest Descent는 매번 gradient의 반대 방향만 따라가기 때문에 지그재그로 이동. 반면 Conjugate Gradient는 내려오던 방향의 히스토리와 현재 gradient 반대 방향을 섞어 더 좋은 방향을 탐색. 첫 반복은 히스토리가 없어서 Steepest Descent와 같지만, 이후에는 방향을 비스듬하게 조정해 거의 한 번에 최적점으로 수렴하는 모습을 확인.
“gradient를 서로 잘 섞어준다”는 작은 아이디어가 최적화 성능에 큰 도약을 만들 수 있으며, AI 분야의 여러 최적화 알고리즘도 이런 아이디어를 차용해 조금씩 변형.
